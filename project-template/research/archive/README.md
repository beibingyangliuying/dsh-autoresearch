# `research/archive/` — where a retired document goes, and why it is not deleted

A retired document is **moved here and explained**, never deleted and never rewritten in place:
`research/archive/<what>_<YYYYMMDD>/`, with a `README.md` beside it.

## Why the reason is the valuable part

A rejected direction or a superseded plan has one use left: it stops the next reader from walking the
same road. That use survives only if the file is still here and still says what it said. So:

- **What was retired, where it came from, and what replaced it** — three lines in the folder's
  README. That is the whole requirement.
- **The retired text is not corrected.** Old paths inside it keep pointing where they pointed; the
  folder README gives the mapping to today's names. Editing a retired file to match today's layout is
  rewriting history to be tidy, and it destroys the only thing the file was still good for.
- **Live pointers are the exception.** A document still in use that links into this archive gets its
  link updated — that is the pointer being fixed, not the record being rewritten.

## Rules

- **Retire, do not delete.** If a file is genuinely worthless — a scratch note with no finding —
  it should not have been a document; delete it before it is ever cited, not after.
- **Nothing is retired during a round that is still running.** A direction is retired when a ruling
  or a result retires it, and the ruling is cited in the folder README.
- **A retired document is never a source again.** It is history: quoting it as current evidence is
  the misuse this directory exists to make visible.
- **If a retired file is reformatted or translated**, its README says where the original bytes can
  still be obtained (the commit or the copy that holds them) — a reformat is not a revision, and it
  must not become the only version that survives.
- **Keep the folder count honest in the README, not in prose elsewhere.** A list of what is in the
  archive belongs in the archive's README, where it is next to the thing it describes.
