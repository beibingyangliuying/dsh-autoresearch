# 05 — 修订草案（Revision 27）：分类扫描与渐进式读取的入口

**状态：已执行（2026-10-19，三个提交：`97cd156` `4dbed1b` `81625fa`）。** 起草 2026-10-19 · 裁定者：junhan
· 落地后的理由、两条实测结论与未测边界见 [`../decisions.md`](../decisions.md) §68；本文件保留当时的判据与流程，
不再维护。

**依赖**：[`revision-26.md`](revision-26.md)（研究区收缩到 `references/` 一层）必须先落地——
本纪律的产物写进层根下的 `references/`，否则写进的是一个马上要改掉的路径。

**范围**：新增一份纪律 `collection-sweep`，加一个工具模式 `--collection --screen`。
它只做**入口与排队**：把一个 Zotero 分类变成某课题的候选队列，把摘要级能判的出局判掉，
把在范围内的交给 `reading-triage` 逐篇渐进读、`section-notes` 落节笔记。
它**不**判"读到哪"、**不**写库笔记、**不**裁"借不借"。

---

## 0. 结论先行

1. **单位是（分类 × 课题）**，不是分类、也不是论文。同一分类被第二个课题扫 ＝ 新的一轮，不覆盖。
2. **摘要只判出局**：`depth: abstract` · `verdict: stop` · `basis` 指到摘要哪句。`enough` 永不出现在摘要上。
3. **语料决定的词表就是 `reading-triage` 的现成词表**——出局＝`stop`、排队＝空 verdict、读不了＝`park`。
   本纪律**不新增任何判定词**，只新增"排队与计数"。
4. **产物三样**：台账行（`found via: collection <key> <name>`）· 锚定集补行（若扫的是新分类）· 轮次报告（计数／预算／交接）。
   **不新建目录、不建 corpus 文件。**
5. **章节笔记不在这里写**：读到方法节末才由 `section-notes` 写 `/section-N`；本纪律只负责把论文送到那一步之前。

---

## 1. 现状：三段已有，缺入口

| 环节 | 现有纪律 | 说明 |
|---|---|---|
| 逐篇判"读到哪" | `reading-triage` | `depth`／`verdict`／`basis`／`re-open if`，顺序读，8 片预算 |
| 方法节 → 笔记 | `section-notes` | 一节一条 `/section-N`，头尾故意不写 |
| 借不借 | `adoption-ruling` | A 级读完 + 数值锚点 + 属主裁定 |
| **从分类到队列** | **无** | 11 份纪律里 `collection`／`分类` 零命中 |

证据：两个真实课题的 `references/` 层都已有入口文件
（A 的 `zotero_anchor_map.md`、B 的 `zotero_anchor_set.md`，B 记 14 叶），
A 的 `reading_ledger.md` 已经是按 `reading-triage` 词表写的读态台账。
**缺的不是判据，是"从锚定集枚举出这一轮的候选，并留一次计数"这一步。**

---

## 2. 单位与触发

- **单位**：`(分类 × 课题)`。一行台账仍是 `(论文 × 课题)`；一个分类扫出来的是**这一轮的队列**。
- **触发**：
  - 属主点名"扫这个分类"或"这个课题里哪些文献能用"；
  - 课题新建了 `references/` 层，需要把锚定集里的分类逐叶扫一遍；
  - 一条 `park` 的复看条件成立，且它是分类扫描留下的。
- **不触发**：没有具名课题；只是"看看有没有人做过"（那是 `literature-recon` 的检索）；
  只是读某一篇（那是 `reading-triage`）。

---

## 3. 输入（开读前必须读到的四样）

1. **课题**：`00_scoping.md` 里的问题 id 与"这一问要什么"的一句话（triage §2.1）。
2. **锚定集**：课题 `references/` 里的入口文件（`zotero_anchor_map.md` / `zotero_anchor_set.md`），
   给出"哪个分类是入口、作品数、出处行"。没有它 ⇒ **问属主，不扫全库**。
3. **这一问的台账**：课题 `references/` 下的读态台账（新布局 `ledger.md`；A 用 `reading_ledger.md`）。
   按 `itemKey` 去重；已有当前判定的不重开。
4. **这一轮的预算**：按条目数估字符（见 §5.3），开读前报出来。

---

## 4. 流程

```text
枚举分类（--collection，报 total 与 showing）
  → 去重（按 itemKey；跨分类、跨台账）
  → 分批筛（每批 5 条，摘要级）
  → 写行（出局 stop / 在范围空 verdict / 读不了 park）
  → 交接（在范围的逐篇进 reading-triage；方法节末由 section-notes 落笔记）
  → 报告（计数、预算、实际、没扫到的）
```

### 4.1 枚举

`zotero-read.mjs --collection <key>` 目前只印标题，且 `--limit` 默认 **10**、上限 **100**、**只发一次请求**
（`paginatedJson` 不翻页）。所以这一轮的新模式见 §6；无论用哪种，**`showing < total` 必须响亮报出来**，
不许把截断当"扫完"。

### 4.2 去重

- 同一 `itemKey` 出现在两个分类 ⇒ 一行，`found via` 写第一个扫到的分类，报告里记重复。
- 台账里已有当前 `verdict` 且 `re-open if` 不成立 ⇒ 跳过，报告里记"已判定"。

### 4.3 分批筛

每批 5 条（沿用 `reading-triage` §3.8 的批量口径），一次调用看 5 条的摘要。
判据只有一条：**摘要是否已经足以settle它不能服务本课题**。能 ⇒ 出局；不能 ⇒ 在范围。

### 4.4 交接

在范围的论文**逐篇**交给 `reading-triage`：从论文自己的 §1 顺序读、每个节边界判一次、
读到方法节末由 `section-notes` 写笔记。本纪律不代读、不代判、不代写。

---

## 5. 判据

### 5.1 词表映射（不新增词）

| 扫描结论 | 台账行 |
|---|---|
| 摘要已settle：不能服务本课题 | `depth: abstract` · `verdict: stop` · `basis`: 摘要哪句 · `re-open if` |
| 在范围内、本轮要读 | `depth: —` · `verdict` 空（队列） |
| 在范围内、本轮读不了（无全文／时间） | `depth: abstract` · `verdict: park` · `re-open if` |
| 条目无任何可读附件 | `depth: —` · `verdict: stop` · `basis`: 书目记录即全部证据（triage §4.2） |
| 已有当前判定 | 不动 |

**`enough` 永不写在摘要上**（`reading-triage` §3.2）；本纪律也不写它。

### 5.2 "采用"不在这里判

- 扫描只出**论据级**结论：这篇能不能为本课题的某句话作支撑。
- **借鉴**（把公式／方法搬进代码）是另一条链：A 级读完 + 原文定位 + 归一式 + **数值锚点** + 属主裁定
  （`adoption-ruling`）。进队列**不**等于可借鉴（`INV-ADOPT-3`）。
- `references/` 层的规则（两个课题的 README §1–§2）本来就禁止在此写"采用／不采用"：只写读态，采纳留在
  `prospects/`／`design/`。

### 5.3 预算

- 一轮 = **8 片源文本**（≈96k 字符，triage §3.8），筛选计入。
- 筛：一条摘要 ≈300 字符 ⇒ 34 条约 10k，**一次调用**就够；100 条约 30k，需要分批。
- 读：一篇 33k–88k 字符 = 5–8 片 ⇒ **一个 34 条的分类必然是多个读轮**，开读前就要说清"这一轮只读得完几篇"。
- 报告写：估算、预算、实际读了几片、没读到的。

### 5.4 章节笔记的时机

- 只在一个**方法节读完**时写，一节一条，顶层节（`section-notes` §3.1／§3.3）。
- 读停在 §2 ⇒ 没有 §3 的笔记，报告写 `not reached`，不写"不需要"。
- 本纪律**不写笔记**；它只把论文送到"方法节刚读完"那一步之前。

## 6. 工具：`--collection --screen`

现状：`--collection` 只印 `key · 年 · 类型 · 标题`（`zotero-read.mjs:604-611`），
筛 34 篇要 34 次 `--fulltext`（≈10 万字符），比整轮预算还大。所以这个模式是纪律的**仪器**，不是附赠。

```text
node zotero-read.mjs --collection <key> --screen [--screen-limit 300]
```

输出形状：

```text
collection : ABC12345  "05-3 拓扑结构与网络鲁棒性"  · total 34 · showing 1-34
abstracts  : 31/34 have one · notes/attachments in the collection are skipped (3)
budget     : ~11,200 characters of abstract text

 1. ABCD1234  2024  journalArticle  <title>
    abs: <前 300 字>…
 2. EFGH5678  2023  conferencePaper  <title>
    abs: (no abstract)
```

规则：

- 只筛**父记录**；`note` / `attachment` 行跳过并计数，不算进 34。
- 默认 300 字符/条；34 条 ≈ 11k，在 16k 截断线以内。
- **`showing` 行永远打印**；`total > 100` 且无法分页时必须报"本工具枚举不全"，不许静默。
- 不声称"有没有可读附件"——那要查 children，留给 `reading-triage` 的"无可读文本"分支。

**待实测**：本地 API 是否支持 `start` 分页（支持则加 `--start`，否则 >100 条的集合只能在报告里声明枚举不全）。

## 7. 产物与落点

| 产物 | 位置 | 形状 |
|---|---|---|
| 台账行 | 课题 `references/` 下的读态台账 | 九列，`found via` = `collection <key> <name>` |
| 锚定集补行 | 课题 `references/` 的入口文件 | 分类 key · 名称 · 作品数 · 日期 · 出处行（只加"入口"，不加判定） |
| 轮次报告 | 会话内（必要时进 journal） | 见 §8 |

**不建** `corpus/` 目录、不建"一分类一文件"——语料决定的可持久形态就是台账行；
分类级的信息由锚定集承载，两者都不新造第三份真值。

---

## 8. 报告形状

1. `## 这一轮` — 课题 id、分类 key/名称、日期、锚定集出处行
2. `## 枚举` — total · showing · 跳过（notes/attachments）· 是否截断
3. `## 筛选` — 出局 N（各一行：itemKey · 摘要哪句）· 在范围 M · 读不了 K（无附件）
4. `## 预算` — 估算字符 · 8 片预算 · 这一轮实际读了几片 · 剩下几篇
5. `## 交接` — 交给 `reading-triage` 的 itemKey 列表与顺序；`section-notes` 预期在哪些节产生笔记（只报"预期"，不报"已写"）
6. `## 没扫到的` — 截断、缺附件、跨分类重复、台账里已判定的
7. `## 不判` — 本轮的"采用／借鉴"一个字都不写，理由一行

---

## 9. 排除条件（命中就停，不绕）

| 命中 | 动作 |
|---|---|
| 没有具名课题 | 停，问是哪一问 |
| 分类为空 / key 不存在 | 报，不猜 |
| 课题没有锚定集，且属主没指定分类 | 停，问入口（不扫全库） |
| 枚举被截断且无法分页 | 报"只枚举到 N / total M"，不当作扫完 |
| 同一 itemKey 跨分类 | 按 key 去重，报告记重复 |
| 已有当前 verdict 且 re-open 不成立 | 跳过 |
| 台账位置不明 / 两种层根并存 | 停，问 |
| 分类是"阅读堆"（横跨互不相干的课题） | 停，问这是不是本课题的语料 |
| 想顺手写一条库笔记 | 禁止：笔记只在方法节末由 `section-notes` 写 |

## 10. 接缝

| 纪律 | 接缝 |
|---|---|
| `reading-triage` | 词表、预算、顺序读、8 片分派全部照用；本纪律只提供队列 |
| `section-notes` | 只接"方法节刚读完"的信号；本纪律不碰库 |
| `literature-recon` | 检索轮写 `## Search question` 与候选行；扫描轮只追加 `found via: collection` 行，不写检索叙述 |
| `adoption-ruling` | 不进本流程；触发是"要搬公式"，不是"进了语料" |
| `metadata-query` | 只补题录标识符，不参与筛 |
