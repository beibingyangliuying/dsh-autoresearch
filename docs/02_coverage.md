## 三、两条外部通道与它们的工具入口

两条通道都**不是挂载的服务器**，是本预设自带的程序：不用它就不花任何成本（[`../protocol.md`](../protocol.md) §6）。

| 通道 | 覆盖什么 | 边界 |
|---|---|---|
| 预印本索引 · [`tools/arxiv.mjs`](../tools/arxiv.mjs) | 检索索引、按标识符读一条记录、把整个响应收敛到摘要预算 | 一次运行只发**一个**请求（索引每三秒允许一次，绝不循环）；默认按**相关度**而非日期；**不含全文**——上游失败被拒绝打印，而不是当成一条记录打印 |

Revision 12 是实测边界，不是偏好）——它把一份清单交给你，删除由你在参考管理器里做，因为那是可撤销的那条路。

## 四、"指定一篇文献，然后呢"

这一段是你此前只从对话里得到过的东西。以**读一篇方法论文并留下逐节笔记**为主线：

### 1. 读之前：先查读过没有

`research/literature/refs/` 里一条参考文献一行（key · 年份 · 等级 · 标签 · 一行 digest）。命中说明读过了；
`B` 行说明**只读了摘要，全文还欠着**。

### 2. 体检：把"这个条目已经覆盖了什么"先摊开（只读）

```powershell
node tools\zotero-section-note.mjs --item <recordKey>
```

它报两件事：有没有**可读附件**；以及条目上每条已有笔记的**第一段**，加上工具从这条笔记里读到的节号。
收尾两行是判据：

```text
read here   : §7 · §6 · §5 · §4 · §3 · §2     # 工具读得出的节，按顶层节计
judge these : none                             # 工具读不出的笔记 key，交给你读
```

工具读的是**标记**（`<!-- autoresearch-section: N -->`）和**无歧义形态**（`第N节`、`Section N`、`§N`、
罗马数字标题）。它**分不出**"逐节笔记"和"整篇总结"——实测在真实库上，`1. 一段话总结`（是总结）和
`2 仿真结果及分析`（是节笔记）**字面上同形**。所以 `judge these` 里那些，第一段不够就整条打开：

```powershell
node tools\zotero-read.mjs --item <noteKey> --limit 12000
```

### 3. 正文怎么读（这一节回答"要不要 OCR"）

- **本预设不做 OCR。** 读的是**参考管理器自己索引出的全文**（`/items/<attachmentKey>/fulltext`）。
  扫描件能不能出字，取决于库那一侧有没有索引过；工具会打印 `text: N characters · i of n indexed pages`，
  所以"只索引了一部分"看得见；**没索引就明说**"库没有这条附件的索引文本"，纪律要求报"无可读文本"，
  **不许从摘要硬写**。
- **全文按附件索引，不按条目。** 一个条目可能有多个附件，工具按 `PDF → EPUB → HTML` 挑一个，并**明说读了哪一个**
  ——读了哪个文件本身就是证据的一部分。
- **读是阶梯，越便宜越先**：元数据 / 摘要 → `--grep` 定位段落取上下文 → 全文按 `--offset` 切片。
  单次工具结果超过 **8,192 字符**会被裁剪器掐掉中间（留头 4,096 + 尾 1,024），所以长文本**必须切片读**：

  ```powershell
  node tools\zotero-read.mjs --fulltext <recordKey> --limit 12000
  node tools\zotero-read.mjs --fulltext <recordKey> --offset 12000   # 上一片会打印这个 offset
  node tools\zotero-read.mjs --fulltext <recordKey> --grep "标题里的词"
  ```

  实测规模：一篇 17 页论文的索引全文 **76,908 字符**（文献纪律 §7）；逐节笔记实际用到的论文在 **33k–88k** 之间。
- **没有大纲这一级**：这条工具链里没有任何东西返回论文的结构，所以"节边界"只能靠**读**，找到标题就**连同编号原文
  一起记下来**（扫描件的编号常不可读）。

### 4. 判覆盖：谁在讲这一节

读那些第一段，结合**论文自己的**节列表，先出这张表——它就是这一轮的判据：

```text
节号 · 论文自己的标题 · 覆盖它的笔记 key（或 none）· 依据（读它的哪一段判的）
```

与工具 `read here` 的读法**不一致** ⇒ **两边都报、停下**，由你裁定；不许绕开（哪个手写笔记讲的是哪一节，
是你的判断，不是可以写过去的一个细节）。

### 5. 写哪些节、写成什么

- **写**：建模、推导、方法/方法论、算法、证明、假设、被定义的指标或因子、被推导的灵敏度。
  因子论文里一节推一个因子 ⇒ **每节一条**。
- **不写**：摘要、引言、背景、综述、related work、动机、术语表；案例、数值结果、实验、测试系统、验证、仿真、
  讨论、结论、附录、参考文献。整篇是综述、没有任何推导 ⇒ 报"**没有方法节**"并停下，不硬写。
- **一条顶层节 = 一条笔记，多长都行。** 1,500–5,000 字符是**质量信号不是上限**：明显偏长通常是案例内容漏进了
  方法节，明显偏短通常是没读——在报告里说明，**但不许为了落进区间而拆节**。
- 每条笔记：标题行（论文的编号 + 论文自己的标题原文）· 核心两到四句 · 镜像论文自己的小节号 · 值得留下的公式
  （行内 `$…$`，行间 `$$` **独占一行**）· 每个符号首次出现即定义 · 结尾一个小结说明它交给下一节什么。
- **不重复**：工具三种拒绝——该节本身已被某条笔记点名 / 请求子节而父节已整节覆盖 / 顶层节已被分条覆盖。
  **兄弟子节不算覆盖**（有 `3.2` 仍可写 `3.1`——缺的那部分正是下一步要写的）；**被拒绝不要去绕**，报告它。
- `--tidy` 只做**机械**修复（把被吃掉的数学定界符还原成 `$` / `$$`），且只报不改的那部分照报；
  **一条会猜"这个破公式本来什么意思"的修复是换了外衣的重写**。

### 6. 写入四步（每一次都是这四步）

```text
干跑（陈述改了什么）  →  参考管理器的授权对话框  →  --write  →  回读
```

`Allow` 覆盖**这一次**写入；`Always Allow` 是你给这个库的长效授予，存在你机器上、也只能在参考管理器里撤销。
**agent 不许开口要 `Always Allow`**，被拒绝或被撤销的授予永远不当作已授予。回读是**写入发生过的唯一证据**。

### 7. 谁动手写库

一篇**就地做完**。**三篇起**，一篇交给一个子代理：子代理读正文、把笔记正文写到
`<workspace>/.section-notes/<recordKey>/` 下的文件并交回一份清单，而**父代理做全部库写与全部回读**。
理由不只是省上下文：库改动是那个被门禁、被审计的动作，把它留在一双手里，"不重复、不覆盖别人的笔记"才是可查的。

### 8. 读完之后的下一步：这篇能借什么

笔记回答"它说了什么"，台账回答"**我们拿什么**"：`research/adoption/<recordKey>.md`，一条一项，
`adopt` / `adopt-modified` / `reference-only` / `reject` 四选一，每项带原文定位、成立条件与"在这里怎么验"、
原文式与我们的归一化式（**分栏，不合并**）、目标模块，以及**测试能断言的数值锚点**。没有锚点的项只能停在
`candidate`——一个抄对的公式和一个实现错的公式，在散文里同形。裁定**是你的**：agent 出候选表，3–5 项一批问你。
**台账不支撑任何结论，但约束代码**：代码与已裁定项不符是缺陷。
