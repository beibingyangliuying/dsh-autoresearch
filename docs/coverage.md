## 一句话

## 一、常驻纪律：每一轮的底色

不在下面表里——它**每一轮都在**，没有触发条件。它管的是话怎么出口：三态标注（事实 / 推断 / 探索）、
不许不可证伪的措辞、不许凭记忆引用、先读后写、三种"没有"要说清是哪一种、决定归所有者、不许静默改契约、
不许越权、子代理的报告是证据不是事实、构造出来的数不是测量、每一轮要重新锚定最初那个请求。
权威文本是 [`../protocol.md`](../protocol.md) §3，**本文不复述条款**。

实验怎么被记录、进度怎么沉淀。

**借鉴与质疑是按需的，不是读文献的步骤。** 读一篇论文不触发它们：`adoption-ruling` 只在要从论文写代码或审计
代码时才加载，`redteam-ruling` 只在已成形的主张要驱动工作、要离开房间或两条路线冲突时才加载。没有触发时它们
根本不在请求里，成本是零——"没跑过"不说明这篇论文没有价值，只说明这一轮没有那个问题。

## 三、三条外部通道与它们的工具入口

三条通道都**不是挂载的服务器**，是本预设自带的程序：不用它就不花任何成本（[`../protocol.md`](../protocol.md) §6）。

| 通道 | 覆盖什么 | 边界 |
|---|---|---|
| 预印本索引 · [`tools/arxiv.mjs`](../tools/arxiv.mjs) | 检索索引、按标识符读一条记录、把整个响应收敛到摘要预算 | 一次运行只发**一个**请求（索引每三秒允许一次，绝不循环）；默认按**相关度**而非日期；**不含全文**——上游失败被拒绝打印，而不是当成一条记录打印 |
| 本地参考库 · [`tools/zotero-read.mjs`](../tools/zotero-read.mjs) 等 | 搜**全文**（默认搜摘要+笔记+附件全文，含付费墙内已持有的一篇）、读一条记录、读一条笔记正文、按片读附件文本、按阶梯读附件本身、看分类树 | 需要桌面端参考管理器**开着**并启用本地 API；读不到索引就明说，而不是看起来像"这条没正文" |

写这一侧的三条共同规矩：**每次写入先陈述改动、且默认干跑**（`--write` 才真写）；**一次调用一件事**；
**写完回读**，回读之前不许报成功。第四件事也有边界：**删除是存在的，但只开一扇小门**（[`../protocol.md`](../protocol.md) Revision 21）：只对 `/retired` 笔记、一次一条、先打印计划与不可逆事实，`--write` 才真删；这个 API 没有回收站，删了不可恢复。整批清理仍在应用里做，因为那是可撤销的那条路。

## 四、"指定一篇文献，然后呢"

这一段是你此前只从对话里得到过的东西。以**读一篇方法论文并留下逐节笔记**为主线：

### 1. 读之前：先看这个课题自己的台账

台账在课题自己的文件里：层根下的 `references/<topic>.md` 的 `## Reference ledger`——层根是课题的
`research/`（若它有这个目录），否则就是课题根（[`../protocol.md`](../protocol.md) §7）——一篇文献一行
（`itemKey · year · found via · grade · depth · verdict · basis · re-open if · date`）。模板里的
`references/ledger.md` **只是这张表的空壳**，第一轮复制成 `<topic>.md` 再写行，不往空壳里写。`depth` 说读到哪
（`—` · `abstract` · `§N` · `full`），`verdict` 说为什么停（`park` · `enough` · `stop`，空 = 还没人判过）。
**别的课题读到哪，用 `grep -n "<itemKey>" <层根>/references/*.md` 看**：同一篇被两个课题读过是正常的，
两个课题各记各的；记录上已有的 `/section-N` 笔记反而是两个课题**共用**的资产；
条目的 `/done` tag 只是你自己打的一个标记，**任何判断都不读它**。

### 2. 读到哪为止：逐节推进，每节判一次

这是 `reading-triage` 管的那一步，也是过去没有出口的那一步。

- **判定按（课题 × 文献）**：这篇对 **Q1** 供的是什么？一句话写不出"这篇供的是 ___" ⇒ 判定就是 `stop`。
  `park` 是等条件、`enough` 是够了、`stop` 是对这个问题不相关——三个词就是三种下一步。
- **默认从前往后顺序读**：`--fulltext <recordKey> --offset 0 --limit 12000`，跟着它打印的
  `next: --offset N` 走；每一片开头就在它所属的那一节里，所以"读到第几节"由读到的文字自己给出，**不需要**
  任何"大纲 → 位置"的映射——那个映射不存在：`--outline` 只给编号和标题，没有页码，也没有字符偏移。
- **每读完一个方法节且判定继续，只报这一节有没有笔记，不代写**——笔记是留给下一个课题的资产，但它
  只在属主点名某一节时由 `section-notes` 生成；你从外部贴入的笔记由 claim 认领（§3）；缺笔记的节
  记进缺口表，claim 轮不代写。
- **可以复用别的课题的笔记**：`zotero-section-note.mjs --item <recordKey>` 一次就打印每条笔记的 tags 和首段；
  首段够用就用，不够再整条读。复用的是**笔记**，不是别的课题的台账行（那一行是对另一个问题写的）。
- **跳读是例外**，三条同时成立才允许：`--outline` 有这一节（编号与标题是论文自己的）·
  `--grep "<标题原文>"` 命中 · **把命中的标题行原文打印出来**。任何一条不成立就退回顺序读——扫描件的标题
  可能被认成 `P SOLUTIOCN`，`--grep` 对真标题会**静默不命中**，那与"这一节不存在"读起来一样。
- **判定落两处**：台账行（`depth` · `verdict` · `basis` · `re-open if` · `date`）与一行 `## Reading log`。
  行不删；判定变了留日期行，不改已经写下的笔记。

### 3. 体检：把"这个条目已经 claim 了什么"先摊开（只读）

```powershell
node tools\zotero-section-note.mjs --item <recordKey>
```

它报有没有**可读附件**；以及条目上每条已有笔记的 **tags** 和**第一段**。收尾五行：

```text
covered     : §2 · §3          # 带 /section-N 的活笔记，按顶层节
retired     : §4 (KEY -> ...)  # 墓碑
legacy      : KEY              # 旧版本留下的整篇总结，不是节笔记
unknown     : KEY · KEY        # 没有 /section- tag 的笔记，交给你读
ambiguous   : KEY              # 带多个 /section- tag，先修
```

工具**不解析正文**：带 `/section-N` 才是覆盖；没带 claim 的进 `unknown`，旧版本留下的 `/digest` 整篇总结单列 `legacy`。读 `unknown` 的第一段；不够就整条打开：

```powershell
node tools\zotero-read.mjs --item <noteKey> --limit 12000
```

然后只有四种动作：`--claim`（内容可用，只打 tag；无 tag 的会同时带 `/imported`）、`--rewrite`（要改格式/正文，原地 + 版本守卫）、`--retire`（垃圾/错误，墓碑），或**不动**（它是整篇总结，不是节笔记）。

### 4. 正文怎么读（这一节回答"要不要 OCR"）

- **本预设不做 OCR。** 读的是**参考管理器自己索引出的全文**（`/items/<attachmentKey>/fulltext`）。
  扫描件能不能出字，取决于库那一侧有没有索引过；工具会打印 `text: N characters · i of n indexed pages`，
  所以"只索引了一部分"看得见；**没索引就明说**"库没有这条附件的索引文本"，纪律要求报"无可读文本"，
  **不许从摘要硬写**。
- **全文按附件索引，不按条目。** 一个条目可能有多个附件，工具按 `PDF → EPUB → HTML` 挑一个，并**明说读了哪一个**
  ——读了哪个文件本身就是证据的一部分。
- **读是阶梯，越便宜越先**：元数据 / 摘要 → `--grep` 定位段落取上下文 → 全文按 `--offset` 切片。
  两处机制各有各的到期时点，不要混成一处：**shell 工具**只在一条命令的输出超过 **16,000 字符**时截到前
  16,000（并明说截了、把全文落到 spill 文件）——所以 12,000 的片**完整到达**；**结果裁剪器**则在**压缩**时
  把超过 **8,192 字符**的工具结果重写成前 4,096 + `[... tool result middle pruned ...]` + 后 1,024——所以一片
  读完之后、上下文一压缩，它的中段就不再可读。切片取工具的默认 **12,000**：它在 16,000 之下（一片完整），
  在 8,192 之上（压缩后必被裁）。因此纪律要求两件事：把**读到的 offset 区间**写进报告，且**不得从被裁的片里
  引用标题或句子**——要用就按 offset 重取。2026-10-19 查清：早先"超 8,192 就当场被掐"的说法把这两处机制
  混成一处，一次 14,999 字符的结果完整到达正是因为它低于 16,000 且当时没有压缩。

  ```powershell
  node tools\zotero-read.mjs --fulltext <recordKey> --limit 12000
  node tools\zotero-read.mjs --fulltext <recordKey> --offset 12000   # 上一片会打印这个 offset
  node tools\zotero-read.mjs --fulltext <recordKey> --grep "标题里的词"
  ```

  实测规模：一篇 17 页论文的索引全文 **76,908 字符**（文献纪律 §7）；逐节笔记实际用到的论文在 **33k–88k** 之间。
- **读的阶梯有四级，每一级都说明自己是谁**（契约 Revision 17 · `INV-CTX-1`）：①**库索引全文**
  （`zotero-read.mjs --fulltext`，最便宜，也是会缺、会过时的一级——它的输出里现在多一行 `rung` 把这件事说在
  结果里，而不是只写在文档里）；②**文件自己的文字层**（`zotero-pdf.mjs --extract`：补"没索引"的洞，**补不了
  字体编码坏掉的数学**，因为它读的是同一张编码表）；③**论文自带的目录**（`--outline`：论文自己说它有哪些节，
  实测 20 篇里 **11 篇有、9 篇没有**；条目带着论文自己的编号形式，`I Introduction` 映射成 `§1`——而写入侧
  恰好拒绝这种输入，所以映射在这里做）；④**把页面渲成图**（`--render --pages 3`，产物落在工作区
  `.section-notes/<recordKey>/pages/`，用 `read_image` **当图像读**——这是**唯一**能救字体编码坏掉的数学的
  一级，读出来的东西不许当文本引用）。
- **本预设仍然不做 OCR**：四级阶梯里没有识别这一步，扫描件出不出字仍取决于库那一侧；④不识别文字，它把页面
  当图像给人看。

### 5. 判覆盖：谁在讲这一节

读 `unknown` 的第一段，结合**论文自己的**节列表，先出这张表——它就是这一轮的判据：

```text
节号 · 论文自己的标题 · claim 它的笔记 key（或 none）· 依据（读它的哪一段判的）
```

与 tag **不一致** ⇒ **两边都报、停下**，由你裁定；不许绕开（哪个手写笔记讲的是哪一节，
是你的判断，不是可以写过去的一个细节）。

### 6. 写哪些节、写成什么

**这一节只在属主点名某一节、要写或重写时跑**；claim 轮不写正文。

- **写**：建模、推导、方法/方法论、算法、证明、假设、被定义的指标或因子、被推导的灵敏度。
  因子论文里一节推一个因子 ⇒ **每节一条**。
- **不写**：摘要、引言、背景、综述、related work、动机、术语表；案例、数值结果、实验、测试系统、验证、仿真、
  讨论、结论、附录、参考文献。整篇是综述、没有任何推导 ⇒ 报"**没有方法节**"并停下，不硬写。
- **一条顶层节 = 一条笔记，多长都行。** 1,500–5,000 字符是**质量信号不是上限**：明显偏长通常是案例内容漏进了
  方法节，明显偏短通常是没读——在报告里说明，**但不许为了落进区间而拆节**。
- 每条笔记：标题行（论文的编号 + 论文自己的标题原文）· 核心两到四句 · 镜像论文自己的小节号 · 值得留下的公式
  （行内 `$…$`，行间 `$$` **独占一行**）· 每个符号首次出现即定义 · 结尾一个小结说明它交给下一节什么。
- **不重复**：工具只拒绝一种——该顶层节已被活笔记 claim。**没有父/子归并**：子节键既不写也不读；旧子节笔记
  进 `unknown`，迁移时合并或退休。**被拒绝不要去绕**，报告它。
- **没有 `--tidy`**。公式坏了只能由 agent 读文字层/页图后重写正文；工具不自动修。
  已 claim 的记录不能原地改写：退休 + 新写；带 `/imported` 的粘贴笔记可以 `--rewrite` 原地改。

### 7. 写入四步（每一次都是这四步）

```text
干跑（陈述改了什么）  →  参考管理器的授权对话框  →  --write  →  回读
```

`Allow` 覆盖**这一次**写入；`Always Allow` 是你给这个库的长效授予，存在你机器上、也只能在参考管理器里撤销。
**agent 不许开口要 `Always Allow`**，被拒绝或被撤销的授予永远不当作已授予。回读是**写入发生过的唯一证据**。

### 8. 谁动手读、谁动手写

**库写与回读只属于一双手，就是父代理**。子代理只读：把笔记正文写到
`<workspace>/.section-notes/<recordKey>/` 下的文件并交回一份清单，从不碰库。

谁**读**按本轮读进去的源文本算，不按篇数算：预算 **8 片（≈96,000 字符）**，见
`reading-triage` §3.8。跨篇的轮次先按 5 篇一批筛摘要（一篇一次 `--fulltext --limit 3000`，
摘要 + 全文长度 + 索引这一级答不答得出，一次拿全）；超过预算就把**尚未开始**的论文各交一个子代理，
已经开始的读完再交——半篇交出去就是读两遍。理由有两层：省上下文，以及库改动是那个被门禁、被审计的
动作，把它留在一双手里，"不重复、不覆盖别人的笔记"才是可查的。

### 9. 读完之后的下一步：这篇能借什么

笔记回答"它说了什么"，台账回答"**我们拿什么**"：`<层根>/adoption/<recordKey>.md`，一条一项，
`adopt` / `adopt-modified` / `reference-only` / `reject` 四选一，每项带原文定位、成立条件与"在这里怎么验"、
原文式与我们的归一化式（**分栏，不合并**）、目标模块，以及**测试能断言的数值锚点**。没有锚点的项只能停在
`candidate`——一个抄对的公式和一个实现错的公式，在散文里同形。裁定**是你的**：agent 出候选表，3–5 项一批问你。
**台账不支撑任何结论，但约束代码**：代码与已裁定项不符是缺陷。
